# ADR-0004: 支付定责只依据验签事件或服务端查询

- 状态：accepted
- 日期：2026-08-18
- 批次：B02
- 决策者：payment-platform-architecture payment-platform-security
- 关联需求：PAY-REQ-0011, PAY-REQ-0019
- 关联控制：NN-03, NN-08, CTRL-002
- 取代：无

## 背景

同步回跳、SDK 回调与页面状态完全在攻击者可控范围内；历史上大量支付欺诈正是通过伪造成功页或重放通知诱导履约。

## 决策

支付最终状态只能由（a）通过完整验签且与商户号、订单号、金额绑定的渠道事件，或（b）平台主动向渠道查询的结果确定。客户端结果仅用于交互提示。

## 后果

用户体验上需要“支付结果待确认”中间态；换来的是伪造成功无法造成履约。

## 备选方案

（a）信任客户端 + 事后对账纠正：拒绝，已发生的履约不可撤销；（b）只依赖回调不做主动查询：拒绝，回调可能丢失。

## 验证

禁止流 FF-04；B37/B39/B114 的伪造与重放夹具。
