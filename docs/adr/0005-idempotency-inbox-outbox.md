# ADR-0005: 幂等键加持久 Inbox/Outbox 实现恰好一次业务效果

- 状态：accepted
- 日期：2026-08-18
- 批次：B02
- 决策者：payment-platform-architecture
- 关联需求：PAY-REQ-0003, PAY-REQ-0020
- 关联控制：NN-04, CTRL-003
- 取代：无

## 背景

渠道与消息层只能保证至少一次；网络超时、重试与用户重复点击都会产生重复请求。分布式事务在跨 PSP 场景不可用。

## 决策

所有产生外部或资金副作用的操作必须携带幂等键并落唯一约束；入站渠道事件进持久 Inbox 去重，出站事件走 Outbox 与本地事务同提交。不声称传输层恰好一次，只声称业务效果恰好一次。

## 后果

需要为每类操作设计幂等键与载荷哈希；重复请求返回首次结果，载荷不一致返回冲突。

## 备选方案

（a）跨服务分布式事务：拒绝，渠道不参与两阶段提交；（b）仅靠数据库唯一索引不做 Inbox：拒绝，无法回放与审计。

## 验证

B12/B36/B115 的并发、重复、乱序与时钟测试。
