
# 支付平台不可妥协规则

1. **业务订单不迁入支付中台。** 原项目拥有商品、库存、履约与业务订单；平台仅拥有支付事实。
2. **不托管原始卡数据。** 不存储或记录 PAN、CVV、磁道、PIN、完整可复用钱包明文令牌；卡支付使用 PSP 托管字段与令牌化。
3. **不以客户端成功为准。** 同步回跳、SDK 回调和页面状态只能提示；履约依据必须是验签 Webhook 或服务端查询。
4. **所有副作用幂等。** 创建、确认、捕获、退款、补单、Webhook、事件消费、账本过账和履约通知均需唯一约束与重放安全。
5. **金额使用最小单位整数。** 禁止 float/double；舍入规则、币种小数位和汇率来源必须受版本控制。
6. **账本不可修改。** 财务修正使用反向或调整分录；历史分录禁止 UPDATE/DELETE。
7. **密钥不落地。** 私钥和 API 密钥由 KMS/HSM/Vault 管理，轮换具有重叠窗口、审计和演练。
8. **回调先验签。** 先验证签名、时间、nonce、序列号和商户/订单/金额，再持久化和处理。
9. **严格租户隔离。** API、数据库、缓存、消息、对象存储、日志、导出和运维工具都必须验证租户上下文。
10. **禁止开放重定向。** return_url、notify_url、支付链接和二维码只接受登记域名或不可变内部路由。
11. **高风险操作四眼复核。** 生产凭证、退款阈值、路由、密钥、人工账本调整、Webhook 回放和发布需要职责分离。
12. **证据不足即失败。** 无自动测试、无运行证据、无恢复演练、无独立审查，不得宣称生产就绪。
13. **不做无牌资金中介。** 默认不提供自有余额、储值、资金池、跨商户清分或代收代付；结算由持牌机构直达商户。
14. **日志最少化。** 默认拒绝记录请求全体、支付令牌、身份证件、银行卡、密钥、完整地址或不必要个人信息。
15. **安全例外有期限。** 每个例外必须有风险所有者、补偿控制、到期日和自动阻断复审。
