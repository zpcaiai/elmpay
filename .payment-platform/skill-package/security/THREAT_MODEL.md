
# 支付平台威胁模型

## 高价值资产

渠道私钥/API 密钥、商户号和证书；Payment Intent 与 Attempt；支付/退款最终状态；复式账本；渠道账单与银行文件；管理员与财务身份；业务项目 Webhook 密钥；个人信息；发布制品和 CI 身份。

## 信任边界

用户浏览器/移动端、业务项目、公共边缘、支付核心、连接器、渠道、管理员后台、数据层、消息层、KMS/HSM、CI/CD、云控制面、第三方监控和邮件/短信。

## 主要攻击者

外部欺诈者、钓鱼团伙、机器人/撞库者、渠道凭证窃取者、供应链攻击者、恶意或被攻陷商户、内部人员、被攻陷运维终端、DDoS 攻击者和财务欺诈者。

## 必须覆盖的滥用案例

1. 伪造支付成功通知或重放真实通知，诱导业务项目履约。
2. 修改金额、币种、商户号、订单号、return_url 或渠道参数。
3. 在支付创建/捕获/退款超时后重复调用造成双扣或双退。
4. 跨租户读取订单、重放 Webhook、使用其他项目商户凭证。
5. 攻陷后台后批量退款、修改路由、导出数据或替换支付证书。
6. 注入第三方脚本窃取卡数据、会话、支付链接或客户信息。
7. 注册同形域名、劫持 DNS、滥发仿冒邮件或替换二维码。
8. 通过 SSRF 访问云元数据、KMS、内部管理端或渠道白名单服务。
9. 通过 SQL/NoSQL/模板/命令注入修改支付状态或提取凭证。
10. 破坏消息顺序、制造毒消息、阻断回调或操纵时钟造成状态分叉。
11. 修改账本或对账差错，掩盖退款、手续费、拒付或结算损失。
12. 通过供应链依赖、CI token、镜像或 IaC 攻陷生产。

每个批次应更新威胁、控制、剩余风险和验证证据。高风险剩余项没有明确风险所有者与到期日时，生产门禁失败。
