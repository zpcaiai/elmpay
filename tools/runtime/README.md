# Runtime policy tools

`control.py` is a dependency-free Python 3 command suite. All gate commands emit
one canonical JSON object and use exit code `0` only for an allowed result; a
policy failure or malformed/missing input exits `2`.

Examples:

```sh
python3 tools/runtime/control.py validate
python3 tools/runtime/control.py render-kubernetes --images /secure/release-images.json
python3 tools/runtime/control.py shadow-diff --baseline baseline.json --candidate shadow.json
python3 tools/runtime/control.py canary --baseline baseline-metrics.json --candidate candidate-metrics.json
python3 tools/runtime/control.py capacity-gate --samples capacity-samples.json
python3 tools/runtime/control.py release-gate --manifest release.json --trust /secure/release-trust.json --external-evidence /secure/external-evidence.json --external-trust /secure/external-trust.json
python3 tools/runtime/control.py external-evidence --bundle /secure/external-evidence.json --trust /secure/external-trust.json --manifest release.json
python3 tools/runtime/control.py go-no-go --manifest release.json --trust /secure/release-trust.json --shadow-baseline baseline.json --shadow-candidate shadow.json --canary-baseline baseline-metrics.json --canary-candidate candidate-metrics.json --capacity-samples capacity.json --operations operations.json
python3 tools/runtime/release_control_cli.py --database /var/lib/elmpay/release-control.db --trust /secure/release-trust.json --rollout-policy platform/rollout/policy.json --release-policy platform/compliance/required-release-gates.json --capacity-policy platform/observability/capacity.json --external-evidence-policy platform/compliance/external-evidence-policy.json --external-evidence-trust /secure/external-trust.json reconcile-rollback --rollout-id "$ROLLOUT_ID" --receipt /secure/rollback-receipt.json
python3 tools/platform_control.py render-service-controls
python3 tools/platform_control.py render-data-plane
python3 tools/platform_control.py restore-gate --report measured-restore.json --backup-digest "$BACKUP_DIGEST"
python3 tools/platform_control.py regional-onboarding-gate --request independently-reviewed-market.json
python3 tools/quality_gate.py model --seed 127 --cases 10000
python3 scripts/run-code-suite.py platform
```

Release trust files contain Ed25519 public keys, explicit identity/role and key
validity/revocation metadata, plus a filesystem-backed replay database. Issuers
use DSSE envelopes; verifiers never receive private keys or shared HMAC secrets.
Human approvals and external evidence are signed over the exact commit,
artifact, image and target binding. This provides deterministic tamper and
replay detection; it does not turn a local run into PCI, legal, UAT,
penetration-test, provider or DR certification.

`external-evidence` is the explicit fail-closed boundary for evidence that must
come from outside this checkout. Its bundle contains independently signed,
release-bound attestations for the Provider, production Kubernetes, DR,
PCI/UAT/penetration, rollout and merchant/legal gates. The command requires
external trust material and validates freshness, distinct verifiers, artifact
digests, measured RPO/RTO, zero rollout side effects and category-specific
semantics. No bundle is generated by the repository. `go-no-go` blocks when the
bundle or its verifier trust material is absent, and local validation never
changes the certification status.

`platform_control.py` is the B88-B111 executable surface. It enforces signed,
tenant/project-bound edge requests with durable nonce/rate state, renders an
exact service-to-service mTLS/network allow-list, renders PostgreSQL/Kafka/Redis
HA resources in two regions, evaluates measured restore/failover input, redacts
telemetry, evaluates SLO/SIEM controls, and applies PCI/regional/regulated-party
boundaries. Durable provider breakers, four-eyes operational actions, incident
state and digest-bound deletion are in `elmpay_runtime`. Production operator
installation, real cloud resources and independent assessment remain external
gates.

`quality_gate.py` and `run-code-suite.py` are the B112-B117 entrypoints. They
run reproducible money/state/ledger properties, account-scoped provider
simulators, webhook fault corpora, concurrency checks, artifact-bound security
scan gates and reusable load profiles. A missing external scanner produces a
blocked/failed result; it is never silently counted as a pass.

The B118-B127 repository-side executors live in `elmpay_runtime`: `uat.py`
emits immutable `CANDIDATE` UAT bundles, `migration_pipeline.py` persists
tenant-scoped checkpoints and redacted shadow diffs, `onboarding.py` stops at
`READY_FOR_EXTERNAL_ACTIVATION`, and `release_control.py` executes signed,
windowed rollout decisions with an actual rollback adapter. `postlaunch.py`
and `postlaunch_worker.py` provide fenced daily/weekly/monthly reconciliation;
`commercial.py` persists pricing, usage, immutable invoices, SLA/support and
four-eyes credit memos. Their schema is
`migrations/V120_127__release_control.sql`. None of these local executors emits
an external approval or changes `NOT_CERTIFIED` on its own.

Completed reconciliation and commercial audit exports retain the exact signed
receipt bytes and immutable result material. A later retry can return the same
durable result after receipt expiry, but any changed tenant, window, manifest,
receipt, signer or digest fails closed.

Rollback dispatch is pre-journaled before the external adapter is invoked. A
lost response or process crash leaves `IN_FLIGHT`/`UNKNOWN` state and blocks
further rollout. `release_control_cli.py reconcile-rollback` accepts only an
Ed25519 DSSE receipt issued by the trusted `rollout_rollback_executor` and
bound to the exact tenant, release, target, current/previous artifacts,
operation id, idempotency key and fence token.
The signed Go/No-Go record also binds every decision-affecting policy digest;
the exact rollout policy is persisted with the rollout so stage definitions
and automatic stop thresholds cannot drift after approval.
